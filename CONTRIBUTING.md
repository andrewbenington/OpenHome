Please review this document before contributing to OpenHome.

## Development Environment

The primary editor most used by OpenHome's developers is vscodium/Visual Studio Code. Contributors are free to use any editor or IDE they would like, but the team may not be able to offer support for issues encountered in other editors.

Some scripts in this repository are designed for Unix environments (e.g. Linux or macOS), run via Bash or Make. These scripts can be run on Windows via the Windows Subsystem for Linux. Most important scripts are PNPM commands, however, which can be run on any platform.

## Generative AI usage

In this section, "AI", "GenAI", "generative AI", and "LLM" refer to generative artificial intelligence tools,
including Large Language Models and similar technologies.

**All contributions are expected to be made by humans, without any AI-generated content.**
You may use AI tools for research, learning, and debugging, but all content in submitted contributions must originate from and be understood by you, the contributor.

This includes, but is not limited to:

- Code
- Documentation
- Artwork, and other visual assets
- GitHub Issues, PRs, discussion posts, and security reports
- Comments and messages in all spaces related to the project,
  both on and off of GitHub

This notably prohibits:

- AI pull request review tools
- AI-generated change summaries in issues and pull requests
- Bug and security reports generated by AI tools

Submission of AI-generated content will result in your issues/PRs being closed.

**Explanation**

At the time this policy is being written, a barrage of AI-generated code, PRs, issues, etc. has put a strain on the already limited time and resources of open source developers. We would rather spend our time working on new features or reviewing human-made contributions than spend time combing through AI code that tends to be verbose, use poor coding practices, and not properly leverage the existing tools of the codebase.

Please note that some AI-written contributions were accepted before the introduction of this policy.
Smaller contributions that would have been identical if written by a human will remain.
Other, larger contributions will eventually be rewritten or removed.

This policy is subject to future change based on developments in the ecosystem and technology.

## Moving to Rust, + Support for New Games + Formats

We are currently transitioning from JavaScript(/TypeScript) implementations of PKM and save file formats to Rust implementations, compiled to Wasm for the frontend. This is being done for the following reasons:

- Rust provides better tools for dealing with binary data, is faster than JavaScript, and gives more control over memory allocation. This is especially helpful for newer game formats, which have multi-MB save files and have heavier encryption algorithms.
- Rust code can be compiled to run on most mainstream devices with no runtime, which really expands the possibilities for companion apps that can share code with OpenHome.
- Rust code can interoperate with other languages if the proper bindings are created/generated. This means any game/ROM hack code in OpenHome's pkm_rs library could in theory be used from C, C++, C#, Python, etc.
